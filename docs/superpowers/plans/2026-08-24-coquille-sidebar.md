# Coquille Sidebar + Menu Utilisateur Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the minimal horizontal nav in `app/(app)/layout.tsx` with a collapsible icon-rail sidebar (Bibliothèque entry only) and a grouped top-right user menu (avatar initials, entreprise name, theme toggle, logout), matching the Supabase-Studio-inspired structure from CLAUDE.md but in NoubinAO's own color palette.

**Architecture:** shadcn/ui's `Sidebar` block (`collapsible="icon"`) provides the icon rail, built-in tooltip-on-hover-when-collapsed, and native mobile drawer behavior — no custom responsive logic needed. A new `UserMenu` client component (dropdown, not the standalone `ThemeSwitcher`/`LogoutButton` components — those stay in place for their existing consumers elsewhere) handles the grouped account menu. A single pure function (`deriverInitiales`) computes avatar initials, TDD-tested.

**Tech Stack:** Next.js 16 App Router, shadcn/ui `Sidebar`/`Tooltip`/`DropdownMenu` (dropdown-menu already installed), `next-themes`, Supabase SSR client, Vitest.

## Global Constraints

- TypeScript strict mode, no `any` in new code (the one pre-existing exception — the untyped Supabase client returning implicit `any` for embedded relations — is inherited, not introduced by this plan; do not attempt to fix it here).
- French UI copy.
- Colors via existing Tailwind theme tokens only — no hardcoded hex. The avatar must use `bg-accent text-accent-foreground` (already verified: 7.09:1 light / 8.37:1 dark contrast, both pass WCAG AA) — do not invent a new color pairing for it.
- Only one sidebar nav entry: "Bibliothèque". Do not add placeholder/disabled entries for unbuilt modules.
- No Cmd+K search box or breadcrumbs in this plan — separate, not-yet-built sub-projects.
- Spec of record: `docs/superpowers/specs/2026-08-24-coquille-sidebar-design.md`.
- Do not delete or modify `components/theme-switcher.tsx` or `components/logout-button.tsx` — both are still used elsewhere (`components/marketing/site-footer.tsx` and `components/auth-button.tsx` respectively). `UserMenu` reuses their *logic* (the `next-themes` hook pattern, the `supabase.auth.signOut()` call), not the components themselves — nesting a full dropdown-triggering component inside another dropdown's content isn't workable.

```ts
export function deriverInitiales(nom: string): string {
  const mots = nom.trim().split(/\s+/).filter(Boolean);

  if (mots.length === 0) return "";
  if (mots.length === 1) return mots[0].slice(0, 2).toUpperCase();

  return (mots[0][0] + mots[1][0]).toUpperCase();
}
```

- [ ] **Step 2: Write the user menu**

Create `components/user-menu.tsx`:

```tsx
"use client";

import { LogOut, Laptop, Moon, Sun } from "lucide-react";
import { useTheme } from "next-themes";
import { useEffect, useState } from "react";
import { useRouter } from "next/navigation";
import { createClient } from "@/lib/supabase/client";
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuGroup,
  DropdownMenuItem,
  DropdownMenuLabel,
  DropdownMenuRadioGroup,
  DropdownMenuRadioItem,
  DropdownMenuSeparator,
  DropdownMenuTrigger,
} from "@/components/ui/dropdown-menu";
import { deriverInitiales } from "@/lib/utilisateur/initiales";

export function UserMenu({
  nomUtilisateur,
  nomEntreprise,
}: {
  nomUtilisateur: string;
  nomEntreprise: string;
}) {
  const [mounted, setMounted] = useState(false);
  const { theme, setTheme } = useTheme();
  const router = useRouter();

  useEffect(() => {
    setMounted(true);
  }, []);

  async function deconnecter() {
    const supabase = createClient();
    await supabase.auth.signOut();
    router.push("/auth/login");
  }

  return (
    <DropdownMenu>
      <DropdownMenuTrigger className="flex items-center gap-2 rounded-md px-2 py-1.5 text-sm hover:bg-accent hover:text-accent-foreground">
        <span className="flex h-7 w-7 items-center justify-center rounded-full bg-accent text-xs font-semibold text-accent-foreground">
          {deriverInitiales(nomUtilisateur)}
        </span>
        <span>{nomEntreprise}</span>
      </DropdownMenuTrigger>
      <DropdownMenuContent align="end" className="w-56">
        <DropdownMenuLabel>{nomUtilisateur}</DropdownMenuLabel>
        <DropdownMenuSeparator />
        {mounted && (
          <>
            <DropdownMenuLabel className="text-xs font-normal text-muted-foreground">
              Thème
            </DropdownMenuLabel>
            <DropdownMenuRadioGroup value={theme} onValueChange={setTheme}>
              <DropdownMenuRadioItem value="light">
                <Sun className="mr-2 h-4 w-4" /> Clair
              </DropdownMenuRadioItem>
              <DropdownMenuRadioItem value="dark">
                <Moon className="mr-2 h-4 w-4" /> Sombre
              </DropdownMenuRadioItem>
              <DropdownMenuRadioItem value="system">
                <Laptop className="mr-2 h-4 w-4" /> Système
              </DropdownMenuRadioItem>
            </DropdownMenuRadioGroup>
            <DropdownMenuSeparator />
          </>
        )}
        <DropdownMenuGroup>
          <DropdownMenuItem onClick={deconnecter}>
            <LogOut className="mr-2 h-4 w-4" />
            Se déconnecter
          </DropdownMenuItem>
        </DropdownMenuGroup>
      </DropdownMenuContent>
    </DropdownMenu>
  );
}
```

The `mounted` guard mirrors `components/theme-switcher.tsx`'s existing pattern (avoids a hydration mismatch since `theme` is `undefined` on the server) — here it only hides the theme radio group, not the whole trigger, since the avatar/entreprise name and logout option don't depend on theme state.

- [ ] **Step 3: Rewrite the layout**

Replace the full contents of `app/(app)/layout.tsx` with:

```tsx
import { redirect } from "next/navigation";
import { createClient } from "@/lib/supabase/server";
import { AppSidebar } from "@/components/app-sidebar";
import { UserMenu } from "@/components/user-menu";
import {
  SidebarInset,
  SidebarProvider,
  SidebarTrigger,
} from "@/components/ui/sidebar";

export const instant = false;

export default async function AppLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  const supabase = await createClient();
  const { data: authData, error } = await supabase.auth.getClaims();

  if (error || !authData?.claims) {
    redirect("/auth/login");
  }

  const { data: utilisateur } = await supabase
    .from("utilisateur")
    .select("id, nom, entreprise:entreprise_id(nom)")
    .eq("id", authData.claims.sub)
    .maybeSingle();

  if (!utilisateur) {
    redirect("/onboarding");
  }

  return (
    <SidebarProvider>
      <AppSidebar />
      <SidebarInset>
        <header className="flex h-14 items-center justify-between border-b px-4">
          <SidebarTrigger />
          <UserMenu
            nomUtilisateur={utilisateur.nom}
            nomEntreprise={utilisateur.entreprise?.nom ?? ""}
          />
        </header>
        <main className="flex-1 p-5">{children}</main>
      </SidebarInset>
    </SidebarProvider>
  );
}
```

The Supabase query is widened from `.select("id")` to `.select("id, nom, entreprise:entreprise_id(nom)")` — a single call now returns the user's own name plus their company's name via the foreign-key embed, instead of needing a second query. Because `entreprise_id` is a many-to-one relationship (each `utilisateur` belongs to exactly one `entreprise`), Supabase returns `entreprise` as a single nested object (`{ nom: string }`), not an array — do not index it like `entreprise[0].nom`.
